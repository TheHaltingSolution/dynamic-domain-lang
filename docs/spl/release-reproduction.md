# Reproducing the bounded SPL release checks

Use the commit named in the release evidence. The [25 November handoff](session-handoff-2026-11-25.md)

## Frozen regression

From the repository on Windows, substitute the full release commit, and choose
fresh output and checkout paths. The short physical checkout keeps generated
module paths within Windows limits. The example assumes the pinned toolchain
and embedded Python are installed under the external project folder.

```powershell
$project = 'C:/Projects/Film_TV_participation_dynamic_DSL'
$python = "$project/environment/python/python.exe"
$leanBin = "$project/environment/elan/toolchains/leanprover--lean4---v4.35.0/bin"
$commit = '<full release commit>'
git worktree add --detach C:/spl-verify $commit
& $python -B C:/spl-verify/scripts/spl_release_verification.py `
  --checkout C:/spl-verify --commit $commit --lean-bin $leanBin `
  --output "$project/artifacts/spl/reproduced-release-a"
```

The runner archives the specified source, fingerprints tracked working bytes
and compiled artifacts, checks compiler identities and import origins, and
records the default and indexed builds and both smoke executables. It then
discovers and runs the full Python suite in one process. The log records per-test
outcomes. The final receipt requires every discovered method to run, zero
failures, errors or skips, and unchanged source and build pins. Use
`progress.json` to monitor an active run and `verification.json` for its final
outcome. Keep a failed run's evidence and use a fresh worktree and evidence
directory for any retry.

For parallel verification, use the same commit and runner in distinct clean
worktrees. Pass a common `--shards N` and a different `--shard-index` from
zero through `N - 1` to each run. Give every shard a separate output path.
After they pass, invoke the runner with `--summarize`, the list of shard
evidence directories and `--output` for the aggregate receipt. Each checkout
has its own registrations and build. The aggregate checks that each discovered
test ran exactly once across the shards.

## Native reserve namespace reproduction

Run this after building the named checkout with the pinned Lake. This runner
uses the tracked registrations and original fixtures. It writes generated
Lean/C and publication contents to a fresh short external path. Use one process
per checkout and preserve the exact generated bytes and output directories.

```powershell
$env:SPL_LEAN_BIN = $leanBin
& $python -B C:/spl-verify/scripts/spl_reserve_stage_conformance.py --output C:/spl-rsv01
```

The runner checks full original-fact oracle results and state for six scenarios,
including ten successors formed from publicly reloaded state. It compares
native emitted results with a separately compiled Python-emitted program.
Each last-period preview has no consumable closing state. The two genuine state
purposes have separate keys for identical financial scope. The cross-purpose
and null-original controls exercise preparation and module admission.

The [retained 24 November scripts](../../validation/retained-harnesses/c09/20261124/README.md)
remain the record of that earlier campaign. The current runner has its own
source and result pins. The fixtures treat calculated results as unissued.
