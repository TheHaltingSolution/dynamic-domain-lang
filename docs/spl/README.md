## Architecture and decisions

```text
Versioned evidence and interpretation -----> reviewed SPL schedule
                                                     |
                                       parse / resolve / type-check
                                                     |
                                         typed immutable core
                                          /                  \
                               reference evaluation       Lean emission
                                                              |
                                                         Lake build
                                                              |
Raw source -> versioned adapter -> validated facts + opening state
                                          \                  /
                                            pure settlement
                                                  |
                               statement / closing state / trace
```

The generated function has no clock, file paths, network access or implicit
prior state. A wrapper supplies versioned facts, parameters and opening balances.
Relations and records are convenient typed views over finite data; lists, maps,
exact numbers and total operations keep the core implementable. Order is explicit
only where it affects economics or observable explanations. Binary floats are
excluded from financial arithmetic in this draft.

The first case is the bounded Skouras–Ventura pilot. Its expected result is
$33,000 earned, $15,000 recovered and $18,000 payable. The second case explores
the selected Lionsgate derivative-work branch structure: different threshold
and payout bases, rolling state, greater-of and reserves. Missing definitions
remain visible as case inputs or research gaps. Neither example claims a
historical replay or complete agreement coverage.

The research update adds three important constraints. LG-01 requires an explicit
broader Contingent Participation Hurdle attestation, independently scoped
work-level gate evidence and a supplied crossed-net worksheet. Two gate endpoint
totals cannot establish that a gate remained clear throughout a period. A
contractual basis-stage video-return reserve remains distinct from the draft's
synthetic post-earnings holdback.

The supplied RQ-07 package now provides a shareable synthetic invoice/bank/
application/cost/funding-to-statement example with the same $18,000 result.
It uses GL posting dates for costs because incurred dates are absent; retain it
as a separately named profile rather than relabeling posting dates as incurred.
The package needs a versioned adapter and canonical schema validation.

Initial compiler implementation should start with the Skouras vertical slice;
the full draft is a target specification, not a demand to implement every
operator immediately. Unsupported constructs must produce diagnostics. The
Lionsgate slice follows when its policy inputs are fixed and independently
calculated. A specification change prompted by implementation should update
the affected reference, schema, expected results and decision record together.

## Repository and compiler handoff

The pinned toolchain is Lean 4.35.0. Start with the existing
[repository setup](../../README.md) and [local Lean references](../lean-resources.md).
Keep the current toy source/runtime/proof and smoke example recognizable as
infrastructure while adding the real language. Proposed future modules are:

| Area | Proposed location and responsibility |
| --- | --- |
| Syntax and checking | `Participation/SPL/`: parser, names, scopes, diagnostics and typed elaboration |
| Core specification | `Participation/Core/`: types, expressions, validation and reference evaluator |
| Lowering and emission | `Participation/Compiler/`: surface lowering and Lean source generation |
| Target runtime | Extend `Participation/Runtime.lean` into modules as needed; exact arithmetic and pure collections |
| Generated cases | Small reproducible modules in `Generated/`; large outputs outside Git |
| Checks and cases | Small public/synthetic fixtures and expected results in future `Tests/` and `cases/` subdirectories |
| Proofs | Scoped new theorems under `Participation/Proofs/`; preserve the toy theorem's limited claim |

These are proposed paths, not existing functionality. A file such as
`Participation/Compiler.lean` can coexist with a `Participation/Compiler/`
directory. Do not replace the toy proof with an unproved participation claim.
No `sorry` or custom axioms are acceptable substitutes for correctness.

Before implementing a slice, record a decision with ID, motivating fixture,
alternatives, chosen draft policy, affected versions and validation evidence.
Then implement independent expected calculations, core evaluation, surface
lowering, Lean emission and end-to-end interchange. Run `lake build`,
`lake exe smoke` and relevant new checks after code changes. Documentation-only
work should check cross-document consistency and links; it does not establish
executable conformance.

Before a held-out exercise, freeze surface/core/schema versions, case-family
split, source digests, policies, build identity, inputs and expected outputs.
Classify a new provision as parameter change, method over existing operations,
surface abstraction, or core extension based on an actual frozen-language
attempt. Because Lionsgate derivative work is used for development, Lionsgate
distribution cannot be advertised as a family-disjoint held-out case. Choose
an independently reserved family and record any prior exposure honestly.
